# KH-109 · Return a request for more information

Sometimes a reviewer can't decide because something is missing (a blurry ID, a missing document). Instead of rejecting, they should be able to send the request back to the citizen.

- The reviewer assigned to a request UNDER_REVIEW can return it to the citizen with a note (the note is required).
- The request moves to a new status, NEEDS_INFO. The note is saved in the request history.
- Returning a request frees the reviewer's slot (it no longer counts toward their limit of active reviews).
- Only the citizen who owns the request can resubmit it. Resubmitting moves it back to SUBMITTED, ready for any reviewer.
- A request in NEEDS_INFO still counts as open: the citizen cannot submit a duplicate for the same service.

Open question: when the citizen resubmits, should it go back to the same reviewer, or to anyone?

Technical hint: add `returnForInfo(id, reviewerId, note)` and `resubmitRequest(id, citizenId)` to `src/requests.js`.

Acceptance: one test per rule. All existing tests still pass. No new dependencies.
