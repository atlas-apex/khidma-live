## What this is

Khidma is a demo slice of a fictional government e-services portal. A citizen submits a request, a staff reviewer starts a review, and the reviewer approves or rejects it. The whole domain lives in one zero-dependency Node module.

## Tech stack

- Language / runtime: JavaScript (ES modules) on Node.js >= 20
- Framework: none. Plain module, no HTTP server.
- Database: none. Requests live in an in-process `Map` and reset on restart.
- Test framework: Node built-in test runner (`node --test`)

## Conventions

- Statuses are `SUBMITTED` → `UNDER_REVIEW` → `APPROVED` | `REJECTED`, or `SUBMITTED` → `WITHDRAWN` (citizen withdrew before review), or `UNDER_REVIEW` → `NEEDS_INFO` → `SUBMITTED` (reviewer asked for more information, citizen resubmitted). Use the frozen `Status` object, never string literals.
- Open statuses for the duplicate guard are `SUBMITTED`, `UNDER_REVIEW`, and `NEEDS_INFO`. Only `UNDER_REVIEW` counts toward a reviewer's `MAX_ACTIVE_REVIEWS`.
- Every request gets a reference number `KH-YYYY-NNNNNN`. The sequence restarts each UTC year.
- Four business-rule errors carry a `code` property: `DUPLICATE_REQUEST`, `REVIEWER_AT_CAPACITY`, `NOT_REQUEST_OWNER`, and `NOT_ASSIGNED_REVIEWER`. Plain validation and state errors carry none. Add a code when you add a new business-rule error.
- `submitRequest`, `withdrawRequest`, `returnForInfo`, and `resubmitRequest` accept an injected `now`. `transition()` takes an optional `now` and an optional `note`, but `startReview` and `decide` do not pass `now` yet. Prefer injected time in new code.
- Tickets ask for one test per rule and no new dependencies. Keep both.
- No TypeScript, no lint config. Write plain ES modules that match the existing style.

## Gotchas

The first four items were true at the 2026-10-15 handover. Issues #10, #11, and #12 track the fixes. Delete each item once its issue closes.

- No lint baseline: style is not checked anywhere. Match the existing file by hand.
- No type checking: signatures are only documented by the tests. Read `test/requests.test.js` before changing an export.
- No coverage threshold: tests can pass with uncovered lines. Add a test for every new branch.
- No CI: `npm test` runs only on your machine. Run it before every push.
- State is per process. The reference-number counter and the store are not shared across processes.
- `startReview(id, reviewerId)` requires a reviewer id and enforces `MAX_ACTIVE_REVIEWS` (5). Tests that need many open requests use the `fresh()` helper to avoid the duplicate guard.
