## What this is

Khidma is a fictional government e-services portal. This repo holds one slice: a citizen submits a request, a reviewer starts a review, and the reviewer approves or rejects it. The store is in memory. There is no persistence, no HTTP API in `src/`, and no authentication.

## Tech stack

- Language / runtime: JavaScript (ESM), Node.js >= 20
- Framework: none. Zero dependencies.
- Database: none. In-memory `Map` store in `src/requests.js`.
- Test framework: Node built-in test runner (`node --test`)

## Commands

Only `test` is defined in `package.json`. There is no build, lint, or run script. The module has no HTTP entry point in this repo.

## Conventions

- Plain JavaScript with no type checking. Keep new code consistent with the existing style: named exports, `Object.freeze` enums, errors with a `code` property.
- Status transitions go through `transition()` so `history` stays complete. Add new statuses to the `Status` enum and to the tests.
- Reference numbers are `KH-YYYY-NNNNNN`. The sequence restarts each UTC year.
- Tests use `resetStore()` in `beforeEach`. Keep tests independent.
- Run `npm test` before every push. There is no CI yet.

## Gotchas

- No lint baseline and no type checking. Style drift is not caught automatically.
- No coverage threshold. A green run does not prove new code is tested.
- All state is in process memory. Restarting the process clears every request.
- The reviewer limit `MAX_ACTIVE_REVIEWS` is 5 and is exported. Tests depend on that value.
- There is no authentication, authorisation, or input validation beyond presence checks. Any HTTP layer added later must supply all three.
